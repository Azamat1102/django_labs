1. Когда QuerySet реально выполняет запрос?

Когда Django действительно нужны данные: например, при переборе QuerySet, вызове list(), len(), bool() или list().

2. Почему prefetch_related() не обязательно означает один запрос?

Потому что Django отдельно загружает основные объекты и связанные с ними данные. Например, проекты одним запросом, задачи вторым, исполнителей третьим.

3. Чем annotate() отличается от aggregate()?
- annotate() добавляет вычисляемые значения к каждому объекту выборки.
- aggregate() вычисляет общий результат для всей выборки.

## Лабораторная работа №5. Атомарность и race conditions

### Реализация

Для передачи владения проектом создана функция `transfer_project_ownership(project_id, new_owner_id)`.

При передаче:
- Проверяется существование нового владельца.
- Старый владелец получает роль MEMBER.
- Новый владелец получает роль ADMIN.
- Обновляется поле `Project.owner`.

### Защита транзакций

Для защиты используется `transaction.atomic()`. Если во время операции возникает ошибка, все изменения отменяются.

`select_for_update()` блокирует строку проекта до завершения транзакции. Также блокируются строки участников проекта в порядке возрастания ID.

### Race conditions и deadlock

При одновременной передаче владения две транзакции могут попытаться изменить один проект. Блокировка строки проекта позволяет выполнять такие операции последовательно.

Чтобы уменьшить риск deadlock, строки блокируются в одинаковом порядке. Deadlock возникает, когда транзакции ждут блокировки друг друга.

### Результаты тестирования

Проверены:
- Успешная передача владения.
- Передача несуществующему пользователю.
- Откат изменений при исключении.
- Две одновременные операции передачи владения.
- Сохранение согласованности Project.owner и Membership.

Конкурентный тест выполняется только на PostgreSQL.

### Контрольные вопросы

**1. Почему atomic не всегда предотвращает гонку?**

Atomic обеспечивает целостность одной транзакции, но не всегда предотвращает одновременное изменение данных разными транзакциями.

**2. Что блокирует select_for_update?**

Он блокирует выбранные строки базы данных до завершения транзакции.

**3. Когда безопасен F() и когда его недостаточно?**

F() безопасен для простых операций с полями базы данных, например увеличения счётчика. Для сложных операций с несколькими таблицами и проверками одной операции F() недостаточно, нужны транзакции и блокировки.
